A raw string arrives with leading whitespace, mixed casing, and spaces that must become a clean URL
slug. Standard JavaScript splits this flow across throwaway variables or turns it inside-out with
nested calls.

## Core Behavior

In standard JavaScript, multi-step transforms take one of two awkward forms. Intermediate variables
carry values one line forward:

```ts
const trimmed = raw.trim();
const lower = trimmed.toLowerCase();
const slug = lower.replace(/\s+/g, "-");
```

Names like `trimmed` and `lower` exist only to wire lines together. Reordering or dropping a step
forces variable renames. Method chaining avoids temporary variables, but only while every step lives
on the object's prototype:

```ts
const slug = raw.trim().toLowerCase().replace(/\s+/g, "-");
```

Adding a standalone helper forces nested wrapping, which reads from the inside out:

```ts
const slug = formatSlug(raw.trim().toLowerCase());
```

## Linear transformations with pipe

`pipe` takes a starting value and passes it left to right through a sequence of single-argument
functions, so execution order matches reading order:

```ts
import { pipe } from "@pplnd/core";

const slug = pipe(
  raw,
  (s) => s.trim(),
  (s) => s.toLowerCase(),
  (s) => s.replace(/\s+/g, "-"),
);
```

Each step receives the output of the previous step, and TypeScript checks every link along the
chain. When a step changes return type, the compiler highlights the mismatched step directly.

## Steps as pure functions

Any unary function can serve as a pipeline step — an arrow function, a named helper, or a
partially applied library function:

```ts
import { Maybe, pipe } from "@pplnd/core";

const displayName = pipe(
  users.get(userId),             // User | undefined
  Maybe.from.nullable,            // Maybe<User>
  Maybe.map((u) => u.name),      // Maybe<string>
  Maybe.getOrElse(() => "guest"), // string
);
```

`Maybe.from.nullable` passes by reference without an arrow wrapper. `Maybe.map((u) => u.name)` takes
only the transform and returns a unary function ready for the piped `Maybe`.

## Reusable pipelines with flow

`pipe` runs immediately on a value. `flow` takes the same sequence of steps and returns a reusable
function instead of evaluating right away:

```ts
import { flow } from "@pplnd/core";

const toSlug = flow(
  (s: string) => s.trim(),
  (s) => s.toLowerCase(),
  (s) => s.replace(/\s+/g, "-"),
);

toSlug("  Hello World  "); // "hello-world"
toSlug("TypeScript Pipes"); // "typescript-pipes"
```

Because `toSlug` is a standard unary function, `Array.prototype.map` accepts it directly without a
wrapper arrow:

```ts
const rawTitles = ["  Clean Code ", " Functional Design "];
const slugs = rawTitles.map(toSlug); // ["clean-code", "functional-design"]
```

Use `pipe` when the input value is already in hand; use `flow` to name and reuse a pipeline.

---

<Aside title="The ten-step limit in pipelines">
`pipe` and `flow` accept up to **10 steps** by design. TypeScript cannot natively infer a variadic
chain where each function's input depends on the previous output without fixed-length overloads, and
large overload sets slow IDE completions across the workspace. Split longer chains into named
sub-pipelines:

```ts
const pricing      = flow(calculateTax, applyDiscounts, calculateShipping);
const fulfillment  = flow(reserveInventory, chargePayment, scheduleFulfillment);
const notification = flow(generateInvoice, sendConfirmation, updateCRM);

const processOrder = flow(validateStock, pricing, fulfillment, notification);
```

Splitting into cohesive phases creates explicit type boundaries and independently testable functions.
</Aside>

## The data-last convention

Every function in `@pplnd/core` places the data value last so configuration and callbacks happen up
front:

```ts
// Data-first: forces wrapper lambdas on every line
pipe(
  option,
  (opt) => Maybe.map(opt, (u) => u.name),
  (opt) => Maybe.getOrElse(opt, () => "guest"),
);
```

With data-last currying, the step returns a unary function that slots into `pipe` and `flow`
without wrapper arrows:

```ts
// Data-last: direct composition without extra lambdas
pipe(
  option,
  Maybe.map((u) => u.name),
  Maybe.getOrElse(() => "guest"),
);
```

## Side effects with tap

`tap` runs a side-effect callback (such as logging or metrics) on the current value and passes that
value onward unchanged:

```ts
import { pipe, tap } from "@pplnd/core";

const result = pipe(
  input,
  parse,
  tap((v) => console.log("Parsed value:", v)),
  validate,
  tap((v) => console.log("Validated value:", v)),
  format,
);
```

Removing a `tap` step leaves the pipeline output untouched.

## Keeping steps focused

Pipelines stay scannable when each line describes one transformation. Extract multi-line closures
into named helpers:

```ts
// Inline block obscures the sequence:
pipe(
  rawInput,
  (s) => {
    const trimmed = s.trim();
    const parts = trimmed.split(",");
    return parts.filter((p) => p.length > 0).map((p) => p.toLowerCase());
  },
);

// Named helper keeps the pipeline declarative:
const parseTokens = (s: string): string[] =>
  s.trim().split(",").filter((p) => p.length > 0).map((p) => p.toLowerCase());

pipe(
  rawInput,
  parseTokens,
);
```
